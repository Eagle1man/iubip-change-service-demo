# Сервис приёма изменений для сайта ИУБиП

Демонстрационная страница внутреннего сервиса, через который проходит **вся
работа по заявкам на внесение изменений на сайт**.

Сотрудник выбирает раздел сайта из списка, заполняет одну форму и отправляет
заявку. Ответственное лицо согласует её либо возвращает — но только по
формальному основанию из закрытого списка. На выходе — готовый файл в формате
Приложения 2 к приказу.

## Что здесь лежит

| Путь | Что это |
|---|---|
| `index.html` | Лендинг: зачем сервис, как устроен, какие правила закрыты, статус |
| `demo/` | Интерактивное демо: вход, форма заявки, очередь, готовый YAML |
| `assets/style.css` | Стили лендинга и демо |
| `tools/serve.mjs` | Локальный просмотр страницы |

## Посмотреть локально

```bash
node tools/serve.mjs . 8081
```

Открыть <http://127.0.0.1:8081/>, демо — <http://127.0.0.1:8081/demo/>.
Внешние зависимости не нужны: это статические файлы.

## Что демонстрация показывает

1. **Идентификаторы подставляются, а не набираются.** Раздел выбирается из
   списка, `id_block`, `url`, `selector` и `block_path` подставляются из реестра
   и заблокированы для ввода. Тип содержимого тоже определяет блок, а не человек.
2. **Возврат — только формальный.** В форме возврата доступны ровно восемь кодов
   (F-01…C-02). Содержательные причины выставить нельзя — их нет и в списке.
3. **Срок считается сам.** Дата изменения + 10 рабочих дней − 3 рабочих дня.
4. **Три уровня ответственности.** Исполнитель, Ответственное лицо,
   администратор сайта.
5. **YAML собирается автоматически** по Приложению 2, имя файла — вида
   `iubip_<id_блока>_<ГГГГММДД>.yml`.

## Данные в демо

Все Ф.И.О., названия разделов и адреса страниц — **вымышленные**. Реальный
Перечень ответственных лиц и реальные адреса разделов сайта в открытый
репозиторий не выкладываются.

## Статус

Готовы этапы 1–2: база, вход, роли из Перечня, выдача паролей, форма заявки,
очередь согласования, коды отказа, сборка YAML.

Этап 3 (генератор реестра блоков) ждёт доступа к страницам сайта. Этап 4
(развёртывание) ждёт внутренней площадки. Пока реестр не заполнен, заявки по
неподтверждённым разделам получают отказ R-01 — намеренно: подставлять
выдуманные адреса сервис не будет.
